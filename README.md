# Coffee Shop Analytics — SQL Deep Dive

Advanced SQL analysis of an 18-month, 3-store specialty coffee chain: 622k transactions, 833k line items, 9k customers. Ten business questions answered end to end, from revenue trends to cohort retention, RFM segmentation, and market basket analysis.

## About the data

The dataset is synthetic, generated by `src/generate_data.py` — and that's deliberate. Real transaction-level retail data at this grain doesn't exist publicly, and generating it meant I could bake in realistic patterns (commuter rush hours, summer cold-drink season, a loyalty program launch, a price increase) and then verify the SQL layer actually finds them. The generator is documented and reproducible with a fixed seed.

Schema: `stores`, `products`, `customers`, `transactions`, `order_items` — a standard retail star layout.

## The ten questions

| # | Business question | SQL techniques |
|---|---|---|
| 01 | How is revenue trending? | LAG, moving-average window frames |
| 02 | When does revenue happen (dayparts)? | CASE bucketing, share-of-total windows |
| 03 | How do stores compare? | Partitioned YoY via LAG(12) |
| 04 | Which products drive profit? | Margin calc, RANK per category |
| 05 | How strong is hot/cold seasonality? | Conditional aggregation with FILTER |
| 06 | Do customers come back? | Cohort analysis, date arithmetic |
| 07 | Which customers matter most? | RFM with NTILE quintiles |
| 08 | What sells together? | Self-join basket analysis, lift |
| 09 | Did the loyalty program work? | Before/after windows anchored per member |
| 10 | Did the Jan 2026 price increase hurt volume? | Comparison-group framing |

Each query lives in its own file under `sql/`, with the business question as a header comment. `src/run_analysis.py` executes all of them against DuckDB and writes results to `results/`.

## Selected findings

**Revenue is growing, driven by traffic rather than basket size.** Monthly revenue roughly tripled over 18 months while average order value stayed flat around $7 — growth is coming from more visits, not bigger orders.

![Monthly revenue](figures/monthly_revenue.png)

**Half of revenue comes from one customer segment.** RFM segmentation puts 2,152 customers (24%) in the "champions" bucket — recent, frequent, high-spend — and they account for 46.5% of all revenue. Meanwhile 528 formerly-frequent customers have gone quiet ("at risk regulars"); at ~$920 average lifetime spend each, that's the highest-value winback list the marketing team could ask for.

**Almond croissants belong next to the espresso machine.** The strongest product affinity in the data: milk-based espresso drinks and almond croissants co-occur at 3x the rate chance would predict (lift ≈ 3.0). Butter croissants attach to lattes at 14% confidence. This is the analysis behind "would you like a croissant with that."

**Retention is strong and improving.** Later cohorts hold above 90% month-3 retention. Worth noting cohort quality is partly a mix effect — later cohorts skew toward loyalty members.

![Cohort retention](figures/cohort_retention.png)

**Cold drinks swing from ~14% to ~29% of drink revenue between winter and summer** — a predictable curve that should drive inventory and menu boards.

![Seasonality](figures/seasonality.png)

**The loyalty caveat (honest version).** Members placed 22.9 orders per 90 days before joining vs 32.1 after — but I would not present that +40% as the program's causal effect. The window straddles organic growth, and joiners self-select. Getting a real answer would need a holdout or matched comparison — the kind of design I cover in my [experimentation-toolkit](https://github.com/spatiha/experimentation-toolkit) repo.

**The price increase held.** Espresso volume kept growing after the ~4% January price rise, roughly in line with unaffected categories — no visible demand hit at this magnitude.

## Running it

```bash
pip install -r requirements.txt
python src/generate_data.py    # ~2 min, writes data/ (43 MB)
python src/run_analysis.py     # runs all sql/ queries via DuckDB
```

## Stack

DuckDB (SQL engine), Python (data generation + orchestration), matplotlib (figures), Power BI (dashboard layer).
